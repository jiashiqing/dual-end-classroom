# 01 · 双端架构

## 为什么是「一份源码两个产物」

同一位老师、同一节课，教师端和学生端 60% 的代码是共享的（路由、同步层、存储、工具），30% 是各自独有的，10% 是两端都有的壳。常见的两种做法都有坑：

| 做法 | 后果 |
|---|---|
| 一个 HTML 装两套代码，靠角色页切换 | 文件臃肿；一旦某次只改了其中一套，另一套就停在旧版本。**实际操作中必然分叉** |
| 复制成两份各自维护 | 立刻分叉：修一个 bug 要记得改两次，忘一次就留个隐形炸弹 |

本技能用第三种：**`app.src.html` 是唯一真源，构建时按角色裁剪**。产物里另一端的代码根本不存在，所以不存在"走错流程"的可能，也不存在"只改了一边"。

## 信息架构：页签顺序不是随意的

教师端顶栏（从左到右）：**授课 · 大屏 · 学情 · 控制台**。

| 页签 | 定位 | 一节课点几次 |
|---|---|---|
| 授课 | 上课的主体（讲课/演示），有内容才有这一页 | 一直 |
| 大屏 | 投屏那一屏：进度墙 + 三个 KPI + 排行榜 + 举手 | 挂在那不动 |
| 学情 | 看学生：每关通过人数、卡点、名单、导出 | 3~5 次 |
| 控制台 | 课前设置 + 课中运行控制 | 课前 1 次，课中十几次 |

> 骨架默认只有后三页。**「授课」页取决于你有没有现成课件要投**：有整页 HTML 课件就走"iframe 照搬 + 双缓冲"那条线（不进本骨架，属于另一类工程）；没有就用外部的 PPT/视频，删掉这一页签即可。

两条判断规则：

1. **课上点得最多的放前面**。"看学生"是一节课里最高频的动作，所以学情在控制台之前。
2. **配置项和它驱动的运行时控件必须在同一页**。分组数决定加分卡张数、每关时长决定计时起点——这两样被切在"总控"和"设置"两个页签时，老师改完得来回翻页确认。所以合成一个「控制台」，页内用两个视图（`课堂运行` / `课前设置`）分开，而不是摊成一页：运行视图一节课点十几次，设置视图一节课点 0 次，混在一起容易误触；四块面板塞一页在 1366×768 上也收不住。

两个视图是两块绝对定位/定高的容器，只切 `hidden`，按钮绑定在 `init()` 里做一次——来回切不会丢事件。

## 配置模型：常量 vs 老师可改的设置

分两层，别混：

| 层 | 例子 | 谁能改 | 存在哪 |
|---|---|---|---|
| `CONFIG`（常量） | 关卡列表、上限/下限、心跳间隔、频道前缀 | 改课程时才动，跟着源码走 | 源码里 |
| `cfg`（设置） | 课程名、分组数、每关时长、规则开关 | 老师在上课前设置里随手改 | 教师端 localStorage，随心跳下发 |

```js
cfg = { title:'', groups:8, mins:[10,12,15,12,8], jump:false, real:true }
```

- **`mins` 是数组不是标量**。一个全局 `TIME_SEC` 迟早被要求"第三关能不能久一点"，那时改模型比一开始就用数组贵得多。
- **`groups` 是 2–12 的整数，不是 4/6/8 三选一**。快捷按钮只是给常用值省一次点击。
- **`cfg` 必须整块下发**，学生端才知道课程名叫什么、能不能跳关。它很小（几百字节），每次心跳都带也不心疼。
- **存档要能迁移**。老版本存的 `{minutes:20}` 要在读出来时转成 `mins:[20,20,20,20,20]`，并且**判断要落在存档对象自己身上**（详见 04 D5）。

## 角色标记语法

单行注释即可，构建脚本按行匹配：

```html
<!-- #if T -->
<div class="role-card" id="rc-teacher">…</div>
<!-- #endif -->

<script>
/* #if S */
const S = { /* 学生端全部逻辑 */ };
/* #endif */
</script>
```

| 标记 | 含义 |
|---|---|
| `#if T` | 只在教师端产物里保留 |
| `#if S` | 只在学生端产物里保留 |
| `#if DEMO` | 只在源码页保留（构建两个产物都删掉） |

规则：
- 支持嵌套，但**别超过两层**——嵌套一多就很难看出某行到底属于谁。
- 标记行会被整行删掉，不要同一行写别的代码。
- `#endif` 必须有，`build_dual.py` 会检查未闭合。

## 角色注入

源码里这一行是构建的锚点：

```js
window.__ROLE__ = '';        // 构建时替换为 'T' 或 'S'
const ROLE = (typeof window.__ROLE__ === 'string') ? window.__ROLE__ : '';
```

`ROLE` 决定三件事：启动直达哪个页面、`Store` 用哪个前缀、`Sync` 连哪个频道名后缀。**改这一行就好，别在代码里到处写 `location.search` 判断角色。**

## 状态放哪

| 状态 | 放哪 | 为什么 |
|---|---|---|
| 课堂码、放行关卡、计时、`cfg` | 教师端 localStorage（`de_T_*`） | 老师换浏览器/刷新后还在 |
| 学生姓名/组/进度 | 学生端 localStorage（`de_S_last`） | 掉线重进不用重填 |
| 在线名单、各组分数、举手 | **只在教师端内存** | 学生一关页面就该消失，不需要持久化 |
| 中转地址 | localStorage `<app>_relay` | 换机房不用改代码 |

判断标准：**这条数据在"没人操作"的时候还该存在吗？** 该 → 存储；不该 → 内存。

## 目录与版本

```
项目/
├── app.src.html        唯一源码
├── qr.js               二维码编码器（零依赖，构建时一并复制到 dist）
├── dist/               构建产物（可随时删了重建）
└── 交付说明.txt         给老师看的，不要写技术细节
```

`qr.js` 是唯一的额外运行时依赖，用 `<script src="qr.js">` 引，所以**它必须和 HTML 在同一个目录**。构建脚本会一起拷；手动发文件时漏了它，教师端二维码那块会静默变空（`paintQR` 里 `typeof QRCode === 'undefined'` 兜底成提示文字）。

版本号写三处，一次构建同步：
1. 源码 `<!-- v3 · 2026-11-07 -->`（构建会带进两个产物）
2. `<title>… · v3</title>`（浏览器标签能看见，核对最方便）
3. 说明文档开头

## 构建产物该不该提交

不提交。`dist/` 是派生物，提交了迟早出现"改了源码没重建、发出去的还是旧的"。要发文件就发 `dist` 里的，别手改。
