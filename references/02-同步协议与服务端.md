# 02 · 同步协议与服务端

## 为什么不用第三方 pub/sub

用 GoEasy / Ably / 自建云 MQTT 这类服务的代价，实测过的：

- **key 必须明文写进 HTML**。学生拷走文件（F12 就能看）就能连同一个频道发假消息：改分数、伪造进度、乱发计时。
- 频道名往往是 `前缀 + 4 位课堂码`，4 位数穷举一万次。
- 学校机房断外网是常态，公网通道一断，教师管控全瞎。

所以默认方案是**自己起一个内网服务器**，30 KB，Python 标准库，不装任何依赖。

## 协议

只有两条通道，都是 HTTP：

| 方向 | 请求 | 说明 |
|---|---|---|
| 收 | `GET /events?channel=<频道>` | SSE 长连接。每帧 `data: {"sender":"uXXXX","data":"<消息JSON字符串>"}` |
| 发 | `POST /send` `{"channel","data","sender"}` | 广播给同频道其他人，返回 `{"ok":true,"n":人数}` |

`data` 是**字符串**（再套一层 JSON）而不是对象，是为了和第三方服务的 `message` 语义保持一致，方便将来替换端点。解析时二次 `JSON.parse`。

### 页面端实现要点

```js
Sync.connect(code, onMsg)          // 本班频道 = 'de_v1_' + code，页面主连接
Sync.subscribe(ch, onMsg)          // 另开一条独立连接，返回 {close()}
Sync.send({t:'hb', ...})           // 发到本班
Sync.send({t:'cfg', ...}, LOBBY)   // 第二个参数指定目标频道
```

- 中转地址解析顺序：`?relay=IP:PORT` → `localStorage` → **同源 `location.host`**。最后一条是关键：用服务器打开页面时零配置直连。
- **没服务器就降级**，不要报错弹窗。识别、闯关、答题全部本地跑，只是老师看不到。模板里学生在 2.5 秒后检测到离线会全关开放（自习模式）。
- 收到消息先做 2 秒去重（`Sync._seen`）：重连、多通道并发时同一条会重复触发。

## 为什么需要两个频道

| 频道 | 谁订阅 | 装什么 |
|---|---|---|
| 本班 `de_v1_<课堂码>` | 教师端 + 已报到的学生 | 心跳、进度、举手、加分 |
| 大厅 `de_v1_lobby` | 报到页（还没输码的学生） | 只有 `cfg` + `open` + `code` |

报到页此时**还不知道课堂码**，连不到本班频道，可它正需要"老师设了几组"来画组按钮。所以教师端每次心跳顺手往大厅播一份配置（`Sync.send(obj, ch)` 只改目标频道，不用另开连接）。

- 大厅消息必须**只带配置**：几十个学生还停在报到页，别让他们每 3 秒收一遍排行榜。
- 学生报到成功就 `Lobby.stop()`（关掉那条独立 SSE），之后靠本班心跳继续同步，不多占连接。
- 一台服务器同时开两个班时大厅会串（两个班的 `cfg` 混在一起）。单班场景不管；真要支持多班，把大厅频道名带上课堂码，并让报到页在输码后再订阅。

## 在线状态：靠学生心跳续命

教师端 `OFFLINE_MS = 14000`（14 秒没消息算离线），学生端每 **8 秒**发一条 `{t:'ping'}`。

- **只在切页/交卷/举手时上报的话，学生安静做题一会儿就全员"离线"**——这是最容易被当成"同步坏了"的假故障。
- 教师端 `ping` 分支**只更新 `seen`**，只有「离线 → 在线」那一刻才 `render()`。否则 40 个学生每 8 秒各触发一次全量重绘。
- 学生真的关页面后，教师端名单不要立刻删（老师点名还要看）；`cleanup()` 在 4×`OFFLINE_MS`（约 56 秒）后才清人。

## 服务端八个端点

| 端点 | 作用 |
|---|---|
| `GET /events?channel=` | SSE 下行 |
| `POST /send` | 广播 |
| `GET /s` `GET /t` `GET /m` | 短地址：内部改写路径直接返回学生端 / 教师端 / **手机遥控台** HTML（`/score` `/remote` 同义） |
| `GET /netinfo` | 告诉页面"这台机器在局域网里是哪个地址"，二维码和学生机地址都靠它 |
| `GET /healthz` | 各频道订阅数，排障用 |
| `POST /api/llm` | **大模型转发**：学情页把数据交给厂商，服务端负责绕 CORS 与归一化 SSE |

`/netinfo` 的返回：

```json
{"ok":true,"port":8099,"ip":"192.168.3.87","ips":["192.168.3.87"],
 "studentUrl":"http://192.168.3.87:8099/s","teacherUrl":"…/t","localUrl":"http://127.0.0.1:8099/t"}
```

端口取 `self.server.server_port`（真在听的那个），不是命令行参数——`--port` 被占时会自动顺延。

`/m` 只是把 `遥控台.html` 原样吐出去，它自己连 `/send` 与 `/events`：手机页**不落账、不改状态**，只发意图 —— `{t:'mscore',g,d}` 加分、`{t:'mlv',lv,on}` 放行、`{t:'mtimer',act}` 计时；教师端收下落账后广播 `{t:'gpts',n,pts}` 与 `{t:'ctl',open,sec,run,mins,lv}` 回来。这样两台手机同时点、手机和教师机同时点都不会重复计分或把关卡状态改乱。

### `POST /api/llm` 怎么转

```
浏览器 ──POST /api/llm {mode, base, model, key, system, prompt, stream}──▶ 本机服务器
                                                                          │
                     data:{"t":"增量"} ◀── 归一化 ◀── 厂商 SSE ◀──────────┘
```

- `mode` 三个值：`openai`（含 DeepSeek / Kimi / 通义 / GLM / 豆包 / 硅基流动 / OpenRouter / Ollama / 任何兼容网关）、`anthropic`、`gemini`。URL 由 `base` 拼：openai 走 `base + /chat/completions`，anthropic 走 `/messages`，gemini 走 `/models/{model}:streamGenerateContent?alt=sse`。
- 三家的 SSE 帧长得完全不一样（`choices[0].delta.content` / `content_block_delta.delta.text` / `candidates[0].content.parts[].text`），**服务端统一抠成 `{"t": "…"}`**，页面只解析这一种——这是"换厂商不改前端"的关键。
- 错误也归一化：上游 401/404 的 JSON 压成一行人话塞进 `{"err": "上游 401：Invalid API key provided"}`，页面只管显示。
- **只允许 https**；只有 `127.0.0.1` / `localhost` 放行 http（给 Ollama、本地网关用）。不这么限，这台服务器就成了"内网任意地址的 POST 代理"。
- **本机地址必须绕过系统代理**：机房电脑常年挂着代理，`build_opener(ProxyHandler({}))` 直连回环；外网地址才沿用环境代理（浏览器能开页面说明代理是通的）。
- 流结束时**必须补 `0\r\n\r\n`**（chunked 结束块），见"必须写对的细节"。

## 服务端必须写对的细节

0. **静态服务要支持 Range（有视频/大图时是硬要求）。** 标准库 `SimpleHTTPRequestHandler` 只认"整个文件 200"，不认 Range。页面上只要有一个 `<video preload="metadata">`，浏览器就只能把整段视频拉下来，占着同源连接，其他请求全排队——实测切页要等十几秒。补上 `206 Partial Content` + `Accept-Ranges` + `Content-Range`（越界回 416，多段 Range 退回整份 200），浏览器只要一小段就能拿到 moov、随即断开，切页回到 100~200 ms。**判断"页面慢"还是"服务器被占死"**：同一时刻从顶层 `fetch` 一个静态小文件，看耗时。
1. **SSE 要手写 chunked 帧。** `Content-Type: text/event-stream` + `Transfer-Encoding: chunked`，每帧按 `"%x\r\n" % len + body + "\r\n"` 写。不写 chunked 的话 HTTP/1.1 下浏览器会一直等 Content-Length。
2. **心跳发注释帧 `: hb\n\n`，不要发 `data:`**。`data:` 会触发前端 `onmessage`，学生端会把它当成真消息。间隔 15 秒足够。
3. **主动探活。** SSE 是单向流，服务端不写就发现不了对端断开；而 socket 关闭后的第一次写经常"成功"（进内核缓冲区），只靠写异常判断会漏。心跳时用：

   ```python
   r, _, _ = select.select([self.connection], [], [], 0)
   if r and self.connection.recv(1, socket.MSG_PEEK) == b"":
       break        # 对端已关闭
   ```

   实测：不做这步，一节课下来僵死订阅能把线程和队列占满（30 个学生进出几轮就上百个僵尸）。
4. **单频道队列要有上限**（模板 `QUEUE_MAX=300`）。学生端卡住时队列会一直涨，满了就丢新消息，不能让服务端 OOM。
5. **把"对面先挂了"的异常静音**。学生机刷新、关浏览器、拔网线、合笔记本，都会让 keep-alive 连接硬断，`socketserver` 默认往 stderr 打整段 `ConnectionAbortedError(10053)` traceback。一节课下来黑窗口全是红字，老师以为程序崩了——其实教室里这属于日常。做法：自定义 `QuietServer.handle_error`，吞掉 `ConnectionError`/`TimeoutError`，真故障照旧上报；空闲连接 120 秒回收。
6. **转发类流式接口，chunked 结束块不能漏。** SSE 端点（`/events`）是长连接，客户端断开就结束；但 `/api/llm` 是一次性的流，写完全部帧后必须补 `0\r\n\r\n`。不补的话浏览器 `fetch` 的 reader 会把"没收到结束块就 EOF"当成网络中断，Python 的 `http.client` 直接抛 `IncompleteRead`——探针第一次就是这么红的，而且现象很像"服务器崩了"。
7. **`bind` 成功不代表端口没被占**。Windows 的 `SO_REUSEADDR` 允许抢占已监听端口。先 `connect_ex` 主动连一下，连得上就顺延，最多试 30 个；顺延后**所有打印地址都要用新端口**，并且提醒"如果只是上次的窗口没关，建议先关掉它，否则学生可能连到旧实例"。

## 短地址为什么不走 302

`Location: /%E5%AD%A6%E7%94%9F%E7%AB%AF.html` 这种已编码的中文路径，部分客户端（实测 curl）跟随重定向时会二次编码成 `%25E5…`，直接 404。浏览器和 `http.client` 正常，但不能赌。

做法：`self.path = "/" + quote(文件名)` 然后 `super().do_GET()`，一个请求一个响应，地址栏还停在 `/s`，顺便好记。

## 局域网排查顺序

学生打不开 `http://IP:8099/s` 时，按这个顺序查，别乱试：

1. **是不是同一网段**：学生机 `ipconfig`，教师机 IP 前三段要一样
2. **教师机防火墙**：第一次运行 Python 会弹「是否允许访问网络」，选了「取消」就永远不通；去 Windows Defender 防火墙 → 允许应用 → 勾私有网络
3. **服务器还在跑吗**：黑窗口没关；`http://IP:8099/healthz` 能返回 JSON
4. **IP 变了**：换 WiFi/插网线会导致 DHCP 换 IP，重开服务器看新地址
5. **端口被占**：`netstat -ano | findstr :8099`，换 `--port 8100`

## 要不要支持公网

非要跨校/回家用，正确做法是**反代 + 一个真后端**（账号、房间、持久化），而不是把 pub/sub 的 key 塞进前端。这已经超出"课堂工具"的范围，按需另议。
